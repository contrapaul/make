A guide for high school students

Code with AI, not instead of it.

An AI assistant can write code for you in seconds. But it cannot tell you when that code is wrong. It cannot explain the words that everyone around you is using. And when your project breaks the day before it is due, the problem is still yours. This site is for the parts that stay yours: knowing what a repository is, reading an error message, and asking a good question.

Start with the words

The hardest part of learning to code with AI is not the code. It is the words. Everyone, including the AI, uses words that nobody taught you. Imagine an answer that starts Just clone the repo and run it from the CLI. If you do not know three of those words, the answer is useless. If you paste the commands anyway without understanding them, you can break your project.

So the glossary is the first real page on this site, and you will come back to it often. Every term is explained in plain English. The English term is always shown, so you can find it on a button, in a menu or in an answer from someone else.

What the glossary covers

  • Code and languages: HTML, CSS, Python, functions, libraries.
  • Building a webpage: elements, tags, classes, selectors.
  • Running code: the terminal, the command line, paths, servers.
  • Version control: Git, commits, branches, GitHub.
  • When things break: bugs, debugging, stack traces.
  • Putting it online: hosting, domain names, DNS.
  • Working with AI: prompts, tokens, hallucinations.

Move your mouse over any underlined word on this site to read a short version, without leaving the page.

Both languages, on purpose

  • The glossary has a switch: English or 中文.
  • The English term stays visible in both modes.
  • The Chinese term sits underneath it, not in place of it.
  • Definitions are written twice, not machine translated.

Understand it in the language you think in. Recognise it in the language the tools are written in.

Read it in Chinese, recognise it in English

Almost every menu, button and error message you will see is in English. Imagine a student who learns only 仓库. They understand the idea, but they still cannot find the word repository in GitHub. Another student learns only the English word. They may not understand the idea at all.

That is why the switch never hides the English. When you turn it on, the explanation changes to Chinese. The English term stays in the same place, and the Chinese term appears under it. You get the idea and the word together. You need both to talk about code with other people.

What an AI assistant can and cannot do

A language model predicts text. It is very good at this. Writing code is mostly a text problem, so the results can be impressive. But predicting is not understanding. A wrong answer sounds exactly as sure as a right one. The assistant also cannot see your screen, run your program or know what you tried an hour ago.

This leads to some practical habits. Ask for one piece at a time. Run it. Read the error yourself before you paste it. Commit before you accept a large change, so you can always return. None of this means you should distrust the tool. It means you stay the person who knows what your project does.

Four habits worth having early

  • Never accept a line you could not have written yourself, until you understand it.
  • Run the code after every small change, not after fifty.
  • Give the assistant the real error text, not a description of it.
  • Keep the project in version control from the first day.

The Workflow tab will explain each of these in detail.

Setup

This page takes you from an empty laptop to your own webpage in a browser. It takes about 30 minutes. Do the steps in order. Each step ends with a picture. When your screen looks like the picture, go to the next step.

Your computer

  1. 1 What you need

    • A laptop with Windows 10 or 11, or with macOS.
    • An internet connection. VS Code is a large download: about 250 MB. about 550 MB on a Mac. On school Wi-Fi, this can take a few minutes.
    • At least 2 GB of free space on your drive.
    • About 30 minutes, and the password for your laptop, in case it asks.

    ✓ You are ready when you have all four.

  2. 2 Install VS Code

    VS Code is the code editor you will use. It is free, and Microsoft makes it.

    1. Go to code.visualstudio.com/download.
    2. Click the big Windows button. The installer downloads.
    3. Open the file. Its name starts with VSCodeUserSetup.
    4. Click I accept the agreement. Then click Next.
    5. Click Next again until you see Select Additional Tasks.
    6. Check that Add to PATH is ticked. Also tick the two boxes that start with Add "Open with Code" action. They help you later.
    7. Click Next. Then click Install.
    8. Keep Launch Visual Studio Code ticked. Click Finish.
    1. Go to code.visualstudio.com/download.
    2. Click the big Mac button. A .zip file downloads to your Downloads folder.
    3. Open Downloads. If you see the .zip file, double-click it.
    4. You now have an app called Visual Studio Code. Drag it into your Applications folder.
    5. Open Applications. Double-click Visual Studio Code.
    6. Your Mac asks if you are sure, because the app came from the internet. Click Open.

    If VS Code offers Chinese

    If your laptop is set to Chinese, VS Code may offer to show its menus in Chinese. We suggest you say no, for now. Guides, error messages and answers from Copilot are all in English. Chinese menus will not match them. Every word you need is in the glossary, in both languages. It is your choice, and you can change it later.

    ✓ You are done when VS Code is open and you can see the Welcome page.

  3. 3 The VS Code window

    Learn these five names first. Every step after this one uses them.

    1. Activity Bar: the icons on the far left. Each one opens a view.
    2. Side Bar: the panel next to the icons. Explorer shows your files here.
    3. Editor: the big area in the middle. You write code here.
    4. Panel: the area at the bottom. The terminal opens here.
    5. Status Bar: the thin bar along the bottom edge.

    The Panel may be closed. To open the terminal in it, press Ctrl+`. This is the same on Windows and Mac. The ` key is to the left of 1.

    ✓ You are done when you can point at all five parts on your own screen.

  4. 4 Make a folder and a file

    A website is a folder of files. You will make the folder and the first file now.

    1. In VS Code, click File. Then click Open Folder…
    2. Go to your Documents folder.
    3. Click New folder or New Folder. Name it my-site.
    4. Open my-site. Then click Select Folder or Open.
    5. VS Code asks if you trust the authors of the files. You are the author. Click Yes, I trust the authors.
    6. In the Explorer, move your mouse over MY-SITE. Click the New File… icon.
    7. Type index.html and press Enter. The file opens in the editor.
    8. Copy this code into the file:
    <!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <title>My first page</title>
</head>
<body>
  <h1>Hello! This is my page.</h1>
  <p>I made this with VS Code.</p>
</body>
</html>
    1. Save the file. Press Ctrl+S or Cmd+S.

    A dot on the file's tab means it has changes that are not saved. When you save, the dot goes away.

    Why the name index.html? A browser opens the file with this name first. It is the front page of your site.

    ✓ You are done when index.html is in the Explorer, the code is in the editor, and the tab has no dot.

  5. 5 See your page

    Now you will see your page next to your code. First, you need one extension.

    1. Click the Extensions icon in the Activity Bar. It looks like four small squares.
    2. Type Live Preview in the search box.
    3. Find Live Preview by Microsoft. Check the name of the publisher, because other extensions have similar names.
    4. Click Install.
    5. Click index.html in the Explorer to go back to your file.
    6. Click the Show Preview button at the top right of the editor.

    You can also right-click index.html in the Explorer and click Show Preview. Your page opens next to your code. Live Preview runs it on your own computer, so only you can see it.

    ✓ You are done when you see Hello! This is my page. as a big heading next to your code. This is your first webpage.

  6. 6 Change one thing

    1. In the editor, find the line with <h1>.
    2. Change the words between <h1> and </h1>. Write your name, or anything you like.
    3. Watch the preview. It changes while you type.
    4. Save the file.

    The preview shows your change before you save. A normal browser only shows what is saved. So save each change you want to keep. If you make a mistake, press Ctrl+Z or Cmd+Z to undo it.

    This is the loop you will use for everything. Change one thing, look at the result, then keep it or undo it. The Workflow tab explains this loop in detail.

    ✓ You are done when the preview shows your new heading, and the tab has no dot.
