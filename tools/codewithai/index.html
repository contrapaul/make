A guide for high school students

Code with AI, not instead of it.

An AI assistant will write you code in seconds. What it will not do is tell you when the code is wrong, explain the words everyone around you is using, or take responsibility when the project breaks the day before it is due. This site is for the part that is still yours: knowing what a repository is, reading an error message, and asking a good question.

Start with the words

The hardest part of learning to code with an AI is not the code. It is that everyone, including the assistant, talks in a vocabulary nobody stopped to teach you. An answer that begins just clone the repo and run it from the CLI is useless if three of those words are unfamiliar, and it is worse than useless if you nod along and paste the commands anyway.

So the glossary is the first real page here, and it is the one to come back to. Sixty terms, each defined in plain language, with the English term always shown so you can recognise it on a button, in a menu or in somebody else's answer.

What the glossary covers

  • Code and languages: HTML, CSS, Python, functions, libraries.
  • Running code: the terminal, the command line, paths, servers.
  • Version control: Git, commits, branches, GitHub.
  • When things break: bugs, debugging, stack traces.
  • Working with AI: prompts, tokens, hallucinations.

Hover any underlined word on this site to read the short version without leaving the page.

Both languages, on purpose

  • The glossary has a switch: English or 中文.
  • The English term stays visible in both modes.
  • The Chinese term sits underneath it, not in place of it.
  • Definitions are written twice, not machine translated.

Understand it in the language you think in. Recognise it in the language the tools are written in.

Read it in Chinese, recognise it in English

Nearly every menu, button and error message you will meet is in English. A student who learns only 仓库 has understood the idea but still cannot find the word repository in GitHub, and a student who learns only the English word may not have understood the idea at all.

That is why the switch never hides the English. Turn it on and the explanation becomes Chinese while the term itself stays where it was, with the Chinese term added beneath it. You get the concept and the label together, which is what you need to take part in a conversation about code.

The assistant is a colleague, not an oracle

A language model predicts text. It is very good at this, and writing code is largely a text problem, which is why the results can be remarkable. But prediction is not understanding, and a wrong answer arrives with exactly the same confidence as a right one. It cannot see your screen, run your program or know what you tried an hour ago.

Everything that follows from that is practical rather than philosophical. Ask for one piece at a time. Run it. Read the error yourself before you paste it. Commit before you accept a large change, so you can always get back. None of this is about distrusting the tool; it is about staying the person who knows what the project does.

Four habits worth having early

  • Never accept a line you could not have written yourself, until you understand it.
  • Run the code after every small change, not after fifty.
  • Give the assistant the real error text, not a description of it.
  • Keep the project in version control from the first day.

The Workflow tab will go through each of these properly.
