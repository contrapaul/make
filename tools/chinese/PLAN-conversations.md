**Ordering:** the fonts task runs first (`PLAN-fonts.md`). This page is then built on

## 1. Goal

Add a fourth study tool to the Chinese review site: a "Flash Conversations" page
that shows the 42 numbered cards from `conversations.md` (A1-A21, B1-B14, C1-C7)
as flash cards, with audio playback per card and a site-wide auto-play toggle.

Media files do not exist yet. The page must be built against a fixed file-name
contract so Paul can drop recordings (or generated TTS) into one folder later
and have them work with no code change.

## 3. Decisions taken with Paul

1. **Audio unit:** one file per card, whole exchange (Q then A, with a pause
   between). 42 files, not ~150 line files. No per-line play buttons in v1.
2. **Audio control:** per-card play/stop button **and** a global auto-play
   toggle (auto-play when a card is opened/revealed), persisted in localStorage.
3. **Card display:** hanzi, pinyin and English all visible at once, matching the
   existing vocab cards. No flip-to-reveal in v1.
4. **Plan location:** this file.

## 6. Data schema (generated)

```js
// Auto-generated by build_conversations.py, do not edit by hand
const CONVERSATIONS = [
  {
    id: "a01",              // lower-cased card id, drives the audio filename
    section: "A",           // "A" | "B" | "C"
    num: 1,
    title: "Are you a teacher?",
    lines: [
      { role: "Q", label: "", zh: "你是老师吗？", pinyin: "Nǐ shì lǎoshī ma?", en: "Are you a teacher?" },
      { role: "A", label: "", zh: "对，我是老师。", pinyin: "Duì, wǒ shì lǎoshī.", en: "Yes, I am a teacher." }
    ],
    note: "New words: ..."  // optional, the New words / Note text, rendered muted
  },
  ...
];
```

Notes:
- `label` carries the `(Yes)` / `(No, somewhere else)` hint from section C so the
  answer variant is still distinguishable.
- The audio path is **derived, not stored**: `AUDIO_BASE + id + '.mp3'`, with
  `const AUDIO_BASE = 'audio/conversations/'` as the single place to change the
  folder. No per-card path literals.
- `role` values: `Q`, `A`, `B`, `C`. `B`/`C` only appear as answer variants in
  section C, and section B statements use `role: "S"` (statement).

## 7. Media contract (the important part)

```
tools/chinese/audio/conversations/a01.mp3 ... a21.mp3
tools/chinese/audio/conversations/b01.mp3 ... b14.mp3
tools/chinese/audio/conversations/c01.mp3 ... c07.mp3
```

| Rule | Value |
|---|---|
| Extension | `.mp3` (broadest iOS/Android support, plays inline, no autoplay gesture quirks vs ogg) |
| Naming | card id, lower-case, zero-padded to 2 digits: `a01`, `b07`, `c07` |
| Content | full exchange: Q, ~400 ms pause, A. For C cards, Q then each candidate answer with a pause. |
| Format | mono, 44.1 kHz, ~64-96 kbps (`ffmpeg -ac 1 -ar 44100 -b:a 80k`). 42 short clips should stay well under 3 MB total. |
| Location | committed in the repo, served by Cloudflare Pages. **No CDN, no external TTS host** (AGENTS.md: nothing fetched from another host; audience is on China wifi). |

Missing-file behaviour (before the recordings exist):
- Each card's play button renders in a "pending" state (dimmed `▶`, `title="audio pending"`,
  `aria-disabled`) - not a dead click, not a broken icon.
- Detection: lazy `new Audio(url)`, `preload = 'metadata'`, created on first card
  render per card. `onerror` -> pending; `onloadedmetadata` -> enabled. Probe is
  lazy so 42 requests are not fired on page load; a page-wide banner shows
  "Audio not recorded yet - N of 42 cards ready" once probes settle.
- Auto-play is skipped silently for pending cards.

**Deviation, built 2026-11-08:** readiness uses a lazy `fetch(url, {method:'HEAD'})` per
card near the viewport instead of `new Audio(url)` + `preload='metadata'`. Reason: under
`wrangler pages dev` (and any host with an SPA fallback) a missing file answers `200` with
an HTML page, which an `<audio>` metadata load can read as success. The HEAD probe rejects
an `text/html` content-type, and is awaited by Play-all so an unprobed card is resolved
rather than guessed. See HANDOFF for the reviewer findings behind this.

`check_audio.py` prints the expected list, which files exist, and which are
missing, so Paul has a recording checklist.

## 8. UI

Page layout, reusing existing classes where they exist:

- Topbar `对 · Flash Conversations`, sidebar/tabbar identical to the other tools.
- `mode-tabs` (existing class, from `sentence-builder.html`) for **A / B / C**
  plus **All**. Section captions explain the use: "Questions people ask me",
  "Things I say", "Questions I ask at booths".
- `search-input` (existing class) filters by hanzi, pinyin, English, card id.
- Toolbar row: `自动播放 · Auto-play` toggle (persisted as `cv-autoplay`),
  `播放全部 · Play all` (sequential queue), audio-ready count.
- Card block: `vocab-card` styling as the base, with a `cc-` prefix for new rules.
  - Header row: `A1` badge (`lesson-badge` style) + English title + play button.
  - Line blocks, stacked: hanzi (largest, `var(--cjk)`), pinyin (italic,
    `var(--seal)`), English (muted). Same hierarchy rule as the style.css header:
    "Hanzi is always the largest element of any card."
  - Q and A get a small role glyph (问 / 答 / 说) so a C card's three candidate
    answers stay readable.
  - `note` rendered as a muted small-caps line at the card foot.
- Phone first: one card per row at all widths, 44px minimum play-button target
  (the existing `@media (hover: none)` block already enlarges touch targets -
  add the play button there).
- Keyboard: `space`/`Enter` on the focused play button; `p` plays the first card
  of the visible set. Nothing may depend on hover.
- Dark theme: uses only existing `--ground / --surface / --ink / --soft /
  --faint / --hair / --seal` tokens, so both themes work for free. No literals.

## 9. Audio controller (js/conversations.js)

One shared `Audio` object, not 42:

```js
let current = null;           // card id currently playing
const audio = new Audio();    // single element
function playCard(id)         // stop current, set src, play(), toggle button state
audio.addEventListener('ended', ...)  // advance queue in Play-all mode, else reset button
audio.addEventListener('error', ...)  // mark card pending
```

Rules:
- Playing a card stops any other card (only one sound at a time).
- Auto-play toggle drives whether opening/revealing a card starts playback. It is
  a user opt-in stored in localStorage; it is **not** on by default, because
  browsers block unattended autoplay and a silent page looks broken.
- `Play all` builds a queue from the currently filtered set, in card order.
- Speed control and per-line replay: deliberately left out of v1 (one file per
  card cannot seek to a line). Revisit only if per-line files get made.

## 10. Parser details (build_conversations.py)

Reads `../LearningChinese/conversations.md`, writes `js/conversations-data.js`
plus a `CONVERSATION_COUNTS` block for the index page counts.

- Split on `^### ([ABC]\d+): (.*)$`.
- Speakable line = bullet containing hanzi and ending with an ASCII-parenthesis
  pinyin group. Verified at build time: the pattern finds **77** lines (this plan said 75;
  the split is 28 Q, 35 answer variants, 14 bare statements).
- The following unindented line is the English translation.
- Known edge cases to handle in tests:
  - `A20` / `B3` / `B10` / `B12`: full-width `（ISNS）`, `（IB）` inside the hanzi
    text, and `3D`, `Autodesk Fusion`, `Instagram`, `DeepSeek` as inline Latin.
  - `A20` has `工作。(Wǒ ...)` with no space before the pinyin paren.
  - `C1` answer B contains a mixed prose+Chinese line
    (`不，我们的公司在东莞 (or Guangzhou, ...; use the actual city name). (Bù, ...)`).
    Decision: take the **last** parenthesis group as pinyin, keep the rest in `zh`.
  - `B` section bullets have no `**Q:**` marker -> `role: "S"`.
  - `New words:` / `Note:` -> `note`, never speakable.
- Ids: id lower-cased; validate the set is exactly a01-a21, b01-b14, c01-c07 and
  **fail the build** on any gap, so the audio checklist stays trustworthy.
- Deterministic output: no timestamps, no randomness, so re-running produces a
  clean diff.

   Tone Trainer keeps its sidebar link. Apply in all five pages.
4. **Audio content ownership.** Recording or generating the 42 clips is Paul's,
   per the brief. If generated TTS is chosen, it needs a zh-CN voice and manual
   listening check - a TTS pass on pinyin like `shí'èr` or brand names
   (`DeepSeek`, `Autodesk Fusion`) is the usual failure point. No AI-generated
   media without an explicit ask.
5. **Auto-play default off**, since browsers block unattended autoplay. If the
   intent is "the site speaks at me without clicking", that needs a different
   shape (a guided drill mode), which is a bigger build than this plan.
